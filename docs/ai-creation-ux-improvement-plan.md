# AI 창작 작업 이어가기·실패 안내 개선 계획

## 목적

사용자가 다른 도구나 손으로 만든 이미지에서 이어 작업할 수 있게 하고, AI 작업이 시작되지 않거나 실패할 때 초보자가 원인과 다음 행동을 바로 알 수 있게 한다.

현재 앱의 7단계 제작 흐름, AI 대화·자동 채우기, 기존 결과 보존 원칙은 유지한다. 이번 계획은 입력 이미지 레퍼런스와 작업별 사전 조건·실패 복구 안내를 보강하는 데 한정한다.

## 사용자 문제와 현재 근거

1. 캐릭터를 다른 앱이나 종이에 그려 두어도 캐릭터 시트 생성에 그 이미지를 레퍼런스로 첨부할 수 없다.
2. 일부 이미지 생성 작업은 캐릭터 시트나 콘티 레이어 등 선행 산출물이 없으면 진행되지 않는다. 사용자가 조건을 모르면 실패 이유를 찾느라 헤맨다.

현재 코드는 이미지 Blob을 IndexedDB에 저장하고, 콘티의 포즈 레퍼런스 업로드를 지원한다. 반면 캐릭터 시트 요청은 텍스트 데이터만 서버에 전달한다. 콘티 인물 레이어에는 캐릭터 시트 선행 조건 검사가 있지만 작업별 검사가 같은 방식으로 화면에 안내되지는 않는다. 현재 JSON 프로젝트 백업에는 IndexedDB 이미지 Blob이 들어가지 않는다.

## 설계 원칙

- 기존 제작 순서와 데이터는 유지하고, 사용자가 작업 중인 단계에서 필요한 조치를 안내한다.
- 캐릭터당 참고 이미지 최대 3장을 지원한다. 이는 2026-10-27 사용자 결정이다. 레퍼런스 이미지는 사용자의 기존 설정과 AI 결과를 대체하지 않는 참고 자료로 취급한다.
- 요청을 막는 필수 조건과 품질 향상을 위한 선택 조건을 구분한다. 선택 조건이 빠졌다는 이유로 작업을 불필요하게 차단하지 않는다.
- 실패 문구에는 확인된 원인, 영향받은 작업, 해결 방법을 포함한다. 기존 입력과 승인된 이미지는 실패로 덮어쓰지 않는다.
- 이미지 크기·형식·개수는 현재 API payload 한도와 지원 모델을 검증한 뒤 확정한다. 제한을 화면에 미리 알리고 초과 시 구체적으로 설명한다.

## 권장 범위

### 1차: 캐릭터 시트에 이미지 레퍼런스 연결

- 캐릭터 편집 화면의 캐릭터 시트 영역에 이미지 추가·미리보기·교체·삭제를 제공한다.
- 우선 PNG, JPEG, WebP를 검토하고, 파일 형식 오류·개별 용량·총 전송 크기를 생성 전에 검사한다.
- 참조 이미지는 기존 이미지 자산 저장소를 재사용해 작품과 캐릭터에 연결한다. 재로딩 후에도 보존 여부를 확인한다.
- 캐릭터 시트 생성 요청에 레퍼런스 이미지 데이터를 실제 이미지 입력으로 전달한다. 현재 이미지 생성 호출이 프롬프트만 받으므로, 지원 모델과 이미지 입력 API를 확인하고 서버에서 검증한다.
- 텍스트로 입력한 캐릭터 설정을 계속 우선 기준으로 삼고, 레퍼런스는 사용자가 선택한 외형 요소를 참고하도록 지시한다. 레퍼런스와 텍스트가 충돌하면 임의로 결정하지 말고 사용자가 조정하도록 결과를 안내한다.
- 레퍼런스가 바뀌면 캐릭터 시트의 입력 해시가 달라지도록 하여 오래된 결과를 최신 결과로 오인하지 않는다. 새 시트는 기존 시트를 즉시 덮지 않고 현재의 후보 확인·적용 흐름을 유지한다.
- 프로젝트 JSON 백업에는 이미지가 포함되지 않는 현재 제한을 명확히 알린다. 완전 백업을 지원할지는 별도 결정으로 남긴다.

### 2차: 작업 전 선행 조건과 실패 복구 안내

- AI 실행 버튼을 누르기 전, 현재 작업 종류에 필요한 조건을 검사하고 누락 항목·해당 단계·수정 행동을 알려준다.
- 예: 인물 레이어 이미지를 만들 때 해당 캐릭터의 시트가 없으면 “이 인물의 캐릭터 시트가 없어 인물 그림을 만들 수 없어요”라고 설명하고 캐릭터 단계로 이동하는 행동을 제공한다.
- 콘티 레이아웃, 레이어 이미지, 장면 완성은 조건이 다르므로 작업별 체크리스트를 둔다. 캐릭터 시트가 선택 입력인 작업에서는 필수처럼 차단하지 않는다.
- 오류를 다음 범주로 분류한다: 입력/선행 조건 부족, 파일 형식·크기 문제, 네트워크/시간 초과, 사용량 제한, 안전 차단, 서버/API 설정, 응답 검증 실패.
- 각 안내는 `무엇이 발생했는지 → 지금 작업에 미친 영향 → 사용자가 할 수 있는 다음 행동` 순으로 쓴다. 재시도 가능한 오류에만 재시도 버튼을 제공한다.
- 기술 상세는 진단에 필요한 범위에서만 표시하고 키·토큰·원시 서버 오류 등 민감정보는 사용자 화면에 노출하지 않는다.
- 실패 후에도 입력, 이전에 적용된 시트와 이미지, 다른 단계의 진행 상태를 보존한다.

## A단계 확인 결과·결정 (2026-10-27)

### 이미지 입력 API와 앱 제한

- **생성 방식**: OpenAI Images API의 `images.edit`를 사용한다. 이 endpoint는 이미지 한 장 이상과 prompt로 새 이미지를 만들거나 수정할 수 있다. 단순 `images.generate`는 prompt 기반 endpoint이므로 참고 이미지 전달 경로로 쓰지 않는다.
- **현재 기본 모델**: 코드 기본값 `gpt-image-2.5-sunburst`는 공식 이미지 생성 가이드와 설치 SDK 정의에서 edit 지원 모델로 확인했다. `OPENAI_IMAGE_MODEL` 환경변수로 재정의될 수 있으므로 배포값과 권한은 구현 전에 다시 확인한다.
- **공식 입력 제약**: GPT Image edit은 PNG/JPEG/WebP 입력, 이미지당 50 MB 미만, 요청당 최대 16장을 지원한다고 설치된 `openai@7.17.0` SDK 타입이 명시한다. 앱 API의 이미지 base64 문자열 상한은 항목당 12,000,000자다. 공식 문서의 요청 총량·세부 제약은 [이미지 생성 가이드](https://developers.openai.com/api/docs/guides/image-generation)에서 재확인한다.
- **사용자 결정**: 캐릭터당 참고 이미지 최대 3장.
- **구현 제안(미승인·미검증)**: PNG/JPEG/WebP 원본을 최대 10 MiB로 제한하고, 브라우저에서 긴 변을 2048px 이하로 줄인 후 WebP 최대 2 MiB/장으로 변환하는 안. 이 값은 공식 API 제한이 아니라 브라우저·JSON 전송량을 줄이기 위한 제안이며, 사용자가 승인한 제품 요구사항으로 간주하지 않는다.
- **저장·전송 제안**: 기존 IndexedDB 미디어 저장소를 재사용하고 자산 ID를 작품의 캐릭터에 연결한다. 사용자가 캐릭터 시트 생성 버튼을 눌렀을 때에만 서버/OpenAI로 전송하고, OpenAI Files API에 영구 업로드하지 않는 방안을 제안한다. 저장·삭제 UX는 구현 전 세부 확정한다.
- **백업 제한**: 현재 JSON 프로젝트 백업은 IndexedDB Blob을 포함하지 않는다. 완전 미디어 백업은 별도 과제로 남기고, 레퍼런스 이미지가 JSON에 포함되지 않는 점은 UI에 알린다.
- **미검증 경계**: 배포 플랫폼의 전체 request-body 상한, 환경변수로 override된 실제 모델·권한, 실 API 응답·비용·화질은 확인하지 않았다. 단계 C 전에 배포 경계의 허용량과 제안 변환 기준을 검증해야 한다.

### 작업별 필수 조건 매트릭스

| 작업 | 필수 조건 | 선택 입력·조건 | 현재 코드 근거 |
|---|---|---|---|
| 캐릭터 시트 생성 | 캐릭터 이름 | 참고 이미지, 기타 서사·외형 필드 | `characters/page.tsx`의 `generateSheet`; `requestCharacterSheet` |
| 콘티 레이아웃 설계 | 콘티 요청에 필요한 프로젝트·회차·컷 정보 | 선택 캐릭터 0~4명. 캐릭터 시트는 필수 아님 | `requestStoryboardLayout`; API `characters` 배열 허용 |
| 배경/소품 레이어 생성 | 저장된 콘티와 대상 레이어 | 인물 포즈 이미지는 대상이 인물일 때만 | `requestStoryboardLayer` |
| 인물 레이어 생성 | 저장된 콘티, 대상 인물, 해당 인물의 캐릭터 시트 자산 | 포즈 참고 이미지 | `requestStoryboardLayer`; 서버의 `generateStoryboardLayer` |
| 장면 스케치 | 저장된 콘티, 표시할 아트 요소 1개 이상, 등장 인물 시트 참조 | 레이어별 이미지, 기존 장면 스케치 | `requestSceneImage`; `generateSceneImage` |
| 장면 완성·수정(레이어 방식) | 저장된 콘티, 아트 요소, 등장 인물 시트 참조. 기존 스케치가 없으면 표시 레이어 자산 최신화 | 승인된 기존 장면 이미지 | `requestSceneImage`의 `incomplete`, `missingPeople`, `characterReferences` 검사 |
| 장면 완성·수정(직접 방식) | 저장된 콘티, 표시할 요소 1개 이상, 등장 인물 시트 참조 | 레이어별 래스터 자산은 필수 아님 | `requestSceneImage`의 `referenceMode: "direct"` 경로 |

캐릭터 시트 참조는 **콘티 레이아웃 단계에서는 선택**, 인물 레이어 및 캐릭터가 포함된 장면 이미지 생성에서는 **필수**다. 사전 안내는 이 차이를 유지해야 한다.

## B단계 구현 결과 (2026-10-27)

- 캐릭터 시트 영역에서 참고 이미지 최대 3장을 한 장씩 추가하고, 미리보기·개별 교체·삭제할 수 있다. PNG/JPEG/WebP MIME·파일 서명·실제 이미지 디코딩을 확인하고, 잘못된 파일은 저장하지 않고 이유를 표시한다.
- 원본 Blob은 기존 IndexedDB `webtoon_creator_media`에 `character-reference` 소유 자산으로 저장하고, 작품의 캐릭터에는 자산 ID 목록만 연결한다. 새 캐릭터를 포함한 로컬 프로젝트 저장 후 새로고침해도 이미지가 유지된다. 교체·삭제 시 연결을 갱신한 뒤 해당 작품·캐릭터의 이전 참고 자산만 정리한다.
- 현재 첨부 이미지는 **AI 시트 생성 요청에 전달되지 않는다**. 화면에도 이 점과 JSON 백업에 이미지 Blob이 포함되지 않는 제한을 명시했다. 원본 크기·변환 방식·총 요청 크기는 C단계의 배포 제한 확인 전까지 확정하지 않았다.
- 검증: `npm ci --no-audit --no-fund`, `npx tsc --noEmit`, 수정 파일 ESLint, `npm run build`, `git diff --check` 통과. Chrome 로컬 프로덕션 화면에서 3장 첨부·상한 표시, 새로고침 보존, 교체·삭제 후 새로고침 보존, 실제 내용이 PNG가 아닌 파일의 거부를 확인했다. PC 화면은 가로 넘침이 없었고 모바일 너비에서는 기존 PC 전용 안내가 표시됐다. 외부 AI 호출·배포 검증은 실행하지 않았다.

## C단계 로컬 구현 결과 (2026-10-27)

- 참조 이미지는 생성 버튼을 누를 때 IndexedDB에서 읽는다. 작품 ID·캐릭터 ID·`character-reference` 소유 유형을 확인하고, 자산이 사라지거나 잘못 연결되면 호출 전에 구체적인 재첨부 안내를 보여 준다.
- **로컬 구현 제한**은 원본 10 MiB/장, 전송 사본 900 kB/장, 캐릭터당 3장, 캐릭터 시트 JSON 본문 4 MB다. 900 kB를 넘는 원본은 긴 변 최대 2048px부터 WebP로 점차 줄여 전송하고, 원본 Blob은 보존한다. 화면과 서버가 각각 크기·형식·본문을 검사한다. 공개 사이트 응답의 `Server: Vercel` 헤더와 [Vercel Function 한도](https://vercel.com/docs/functions/limitations)를 근거로, 공식 요청·응답 본문 상한 4.5 MB보다 여유를 뒀다. 이 수치는 OpenAI 자체의 이미지 입력 상한과 구분한다.
- 참조가 있으면 OpenAI `images.edit`의 multipart 이미지 입력을 사용하고, 없으면 기존 `images.generate` 경로를 유지한다. 이미지의 실제 파일 서명을 서버에서 다시 검사한다. 프롬프트는 텍스트 설정을 우선하고 참고 이미지에서 일치하는 외형만 가져오도록 지시한다.
- 참조 자산 ID와 순서를 시트 입력 해시에 포함했다. 참조가 없는 과거 시트의 해시는 유지한다. 생성 도중 또는 후보 확인 중 입력이 바뀌면 이전 입력의 후보를 자동 적용하지 않는다. 기존 승인 시트는 생성 실패와 후보 취소에서 유지한다.
- 검증: 타입 검사, 수정 파일 ESLint, production build, `git diff --check` 통과. `scripts/verify-character-references.cjs`는 클라이언트 자산 소유 검증·해시 변경과 로컬 가짜 OpenAI 서버의 참조 없음→generate, 유효 참조→edit multipart, 잘못된 서명·4장·본문 초과→AI 호출 전 거부를 확인했다. Chrome 로컬 production 화면에서 새 안내가 표시되고 390px에서는 기존 PC 전용 안내가 표시되는 것도 확인했다. 실제 모델의 화질·비용·권한은 증명하지 않는다.
- **운영 설정 확인(2026-10-27, 이번 배포 전)**: Vercel의 `sdjgh-webtoon-creator` 프로젝트 변수에 Production용 `OPENAI_API_KEY`가 있고 `OPENAI_IMAGE_MODEL`은 없다. 연결된 공유 변수도 없다. 당시 운영 배포는 `main`의 `fa086f2`이며, 그 커밋의 코드 기본값 `gpt-image-2.5-sunburst`가 적용되는 구성이다. 비밀 키의 값은 열거나 기록하지 않았다.
- **사용자 검증 항목**: 해당 API 키의 이미지 edit 권한과 실제 유료 요청의 결과를 확인한다. 생성 결과의 JSON 응답도 Vercel 4.5 MB 상한 안에 드는지 측정한다. 배포 성공만으로 실제 생성과 품질 검증이 완료된 것으로 보지 않는다.

## 수용 기준

- 사용자는 캐릭터 단계에서 기존 그림을 추가하고, 생성 전 확인하고, 교체·삭제할 수 있다.
- 선택한 이미지가 실제 캐릭터 시트 생성 요청에 전달되며, 결과가 그 레퍼런스를 반영하는지 검토할 수 있다.
- 입력값 또는 생성에 실패해도 기존 캐릭터 설정과 적용된 시트는 보존된다.
- 작업별로 필수 조건이 무엇인지 실행 전에 알 수 있고, 누락된 조건을 채울 화면으로 바로 이동할 수 있다.
- 오류 안내가 막힌 이유와 해결 행동을 제공하며, 사용자가 문제를 추측하거나 원시 오류를 해석해야만 하지 않는다.
- 기존 포즈 레퍼런스, 캐릭터 시트, 장면 생성, 자동 저장, 프로젝트 전환 동작에 회귀가 없다.
- 지원 파일 형식·크기·총 요청 크기가 제한 안에서 작동하고, 허용 범위 밖 입력은 서버에서도 거부된다.
- 이미지를 포함하지 않는 JSON 백업 제한을 UI와 문서에서 숨기지 않는다.

## 검증 계획

- 단위/스크립트 검사: 파일 형식·크기·전체 payload 제한, 이미지 참조 해시 변경, 작업별 선행 조건 매트릭스, 오류 코드에서 사용자 안내와 행동으로의 매핑.
- API 검사: 이미지 참조가 없거나 유효할 때 요청 스키마, payload 초과 거부, timeout/quota/safety/설정/응답 오류의 분류. 실제 유료 모델 호출과 모의 응답 검증을 구분한다.
- 상태 보존 검사: 이미지 선택·교체·삭제 후 새로고침, 기존 시트가 있는 상태에서 재생성 실패, 작업 중 사용자가 편집한 값, 프로젝트 간 자산 분리.
- 브라우저 검사: 캐릭터 화면에서 첨부부터 시트 후보 확인·적용까지, 미완료 선행 조건에서 안내와 이동 버튼까지 실제 클릭한다. 데스크톱과 좁은 화면에서 입력·오류 문구가 겹치지 않는지 확인한다.
- 회귀 검사: 관련 `scripts/verify-*.cjs`, 타입 검사, 린트, production build 중 변경 영향 범위에 맞는 기존 명령을 실행한다.

## 결정 또는 구현 시 확인할 점

- **결정됨**: 캐릭터당 최대 3장, API의 이미지 edit 경로, 1차 적용은 캐릭터 시트 생성. 파일 형식·저장 세부 방식은 검증/구현 때 확정한다.
- **실사용 검증 필요**: 운영 API 키의 이미지 edit 권한, 실제 유료 API 왕복과 4.5 MB 응답 상한. 제한에 걸리면 출력 압축 또는 전송 방식을 재검토한다.
- 프로젝트 JSON 백업에 이미지를 포함할지는 별도 과제로 둔다. 장면 이미지의 일반 레퍼런스 첨부도 캐릭터 시트 1차 적용 이후 결정한다.
