# 웹툰 메이커 저장 방식 전환

## 2026-11-18 배포 상태

- 스마트 캠퍼스 iframe은 고정 출처의 SSO 메시지를 확인한 뒤 서버 작품 목록을 불러온다. 연결 전에는 작업 화면을 열지 않는다. 서버 저장은 프로젝트·이미지의 응답을 기다린 뒤 완료로 표시한다.
- 스마트 캠퍼스 밖에서 직접 열면 저장 폴더를 선택하거나 기존 권한을 다시 허용해야 작업 화면에 들어간다. 폴더에는 작품 JSON과 이미지를 함께 담은 `webtoon_<작품 ID>.zip`을 자동 저장한다. 재접속 때 폴더의 ZIP을 읽어 브라우저 작업 캐시를 복원하며, 같은 ID의 내용이 다르면 덮어쓰지 않고 중단한다. 폴더 쓰기 실패는 화면에 표시한다.
- 웹툰 API는 스마트 캠퍼스 서버 내부에 두므로 브라우저가 받은 플랫폼 JWT를 메모리에만 보관하고 같은 중앙 서버에 매 요청 제출한다. 중앙 `verifySession`이 현재 자격과 등록 식별값을 매번 확인한다. 별도 앱 서버의 `sessionProof` 교환 경로는 이 구조에는 적용하지 않는다.
- API는 `ACCOUNT_SECURITY_ENABLED=true`가 아니면 403을 반환한다. 중앙 계정 보안 전환과 실제 계정 확인은 스마트 캠퍼스 SEC-01 기록에 따라 완료됐다. 웹툰 API는 전용 비공개 디렉터리를 연결한 뒤 인증 없는 요청에 401을 반환했고, 웹 앱의 허용 출처 CORS 사전 요청은 204를 반환했다.
- 서버 백업은 매일 및 PC 로그인 시 이 PC의 `Project-Archive`로 가져와 SHA-256을 대조한다. 작업 스케줄러 시험 실행은 성공했고 실제 서버의 빈 저장소 압축본을 로컬에서 풀었다. 별도 시험 폴더의 파일도 압축·복원했다. 실제 학생 작품으로 복원한 증거는 아직 없다.
- 분리 작업 트리의 프로덕션 빌드, 변경 파일 ESLint, 서버 저장소·라우터 시험 5개가 통과했다. 웹툰 메이커 `main`의 Vercel Production 배포가 성공했고 공개 주소의 첫 화면·대시보드·안내 페이지에서 새 서버·폴더 저장 안내가 응답한다. 실제 학생 계정의 작품 저장·다른 기기 재열기, 외부 브라우저 폴더 선택과 이미지 ZIP 복원은 아직 검증하지 않았다. 브라우저 자동화는 URL 확인 단계에서 중단되어 실제 사용자 화면 시험을 완료하지 못했다.

## 결정과 현재 상태 (2026-11-03)

- 기본 저장 대상: 스마트 캠퍼스 계정에 연결된 서버의 작품 및 이미지.
- `저장`: 현재 단계의 작업 내용을 서버에 반영하고 성공 응답을 받은 뒤에만 완료로 표시한다.
- `로컬 저장 (작품·이미지 ZIP)`: 작품 JSON과 모든 이미지 원본을 복원 가능한 ZIP으로 내려받는다.
- 단계별 TXT: 작업 문서가 필요할 때만 `더보기`에서 받는다. 최종 PNG/ZIP 다운로드는 작품 출력 기능으로 유지한다.
- 이 절은 최초 계획 당시의 상태를 기록한다. 위의 구현 후보는 아직 운영 배포 전이다.

## 실제 연결 조건

1. 스마트 캠퍼스 운영 `client/src/screens/series/registry.ts`의 `webtoon-maker`는 `authMode: 'platform'`이다.
2. 스마트 캠퍼스 운영 `server/services/app-policy.cjs`에 `webtoon-maker` 별칭이 있고 `content` 정책은 교사·학생 접근을 허용한다. `/api/webtoon`은 같은 중앙 서버에서 토큰을 직접 확인하고 매 보호 요청에 현재 자격 검증을 수행한다. 토큰을 URL, localStorage, 로그에 두지 않는다.
3. iframe은 다른 출처 쿠키에 의존하지 않고 고정 출처 `postMessage`로 받은 토큰을 메모리에 보관한다. 실제 학생 계정으로 iframe을 다시 열었을 때도 전달·만료 처리가 되는지 검증한다.
4. 사용자가 새 Neon 비용을 피하기 위해 기존 OCI 서버를 선택했다. 2026-11-03 읽기 전용 `df -h /` 결과 본인 서버 루트 디스크는 174 GiB 중 130 GiB 사용(75%), 약 45 GiB 여유이고 아내 서버는 184 GiB 중 21 GiB 사용(11%), 약 164 GiB 여유다. 본인 서버의 `/var/lib/docker`가 약 114 GiB이며 Docker는 이미지 중 약 43.7 GB를 회수 가능으로 표시한다. 삭제·정리는 별도 검토 전까지 하지 않는다. 스마트 캠퍼스 인증 API와 같은 본인 서버에 웹툰용 비공개 영구 디렉터리를 별도로 두고 계정당 256 MiB, 이미지 한 개당 10 MiB로 제한한다.
5. 스마트 캠퍼스 OCI 서버에 전용 `/api/webtoon` API가 있다. 앱은 부모 프레임에서 받은 플랫폼 토큰을 URL/localStorage에 넣지 않고 메모리에서만 보관하며 API 요청마다 전송한다. API는 매 요청 중앙 세션과 앱 접근 정책을 검증한다. **2026-11-18 운영 계정 보안 모드는 켜져 있고 저장 디렉터리도 연결됐다.** 보안 모드가 꺼지면 API는 403으로 닫힌다.
6. 작품 JSON과 이미지는 별도 파일로 저장한다. 이미지 업로드 완료 후 작품 스냅샷을 확정해 이미지 참조가 빈 작품이 생기지 않도록 한다. 파일은 원자적 쓰기·충돌 방지·계정 소유권 검사·용량 상한을 적용한다. 서버 밖 백업 및 복구 시험 전에는 단일 OCI 디스크를 유일한 저장 원본으로 전환하지 않는다.

## 전환 순서와 검증 기준

1. 계정 인증 및 계정별 읽기/쓰기 격리: 다른 계정의 ID를 넣어도 작품·이미지를 읽거나 변경할 수 없어야 한다. 자격 철회 뒤 새 요청은 거부되어야 한다.
2. 서버 저장·재열기: 새 작품, 모든 단계, AI 대화, 편집한 컷과 이미지가 다른 브라우저에서도 같은 계정으로 다시 열려야 한다. 서버 성공 전에는 `저장했어요`를 표시하지 않는다.
3. 기존 브라우저 작품 이전: 로그인 후 로컬 작품을 발견하면 사용자에게 서버로 복사할 작품을 보여 준다. 같은 ID의 서버 작품은 덮어쓰지 않고 충돌을 별도로 처리한다. 서버 확인 전에는 로컬 데이터를 지우지 않는다.
4. 서버 작품을 ZIP으로 백업하고 ZIP을 서버 작품으로 복원하는 흐름을 검증한다. 현재 ZIP 기능은 브라우저 저장 작품에만 적용된다.
5. 스마트 캠퍼스 iframe과 직접 연 탭, 태블릿에서 계정 세션·이미지 재열기·ZIP 백업을 검증한 뒤 기본 저장을 서버로 전환한다.

스마트 캠퍼스 저장소와 웹툰 메이커의 다른 미커밋 작업은 각각 분리된 작업 트리에서 보존한다. 운영 서버의 웹툰 API 연결과 이 PC의 외부 백업은 준비됐으며, 웹 앱의 기본 저장 전환과 실제 학생 작품 검증은 배포 단계에서 별도로 확인한다.
